# Segment Impact Profiler

Reusable **offline**, LLM-free analysis of how SHAP contributions differ across
population segments for LightGBM / XGBoost credit-risk models.

## The three visualizations

| Prototype | API | What it answers |
|---|---|---|
| **01 – Feature Impact Flow (Sankey)** | `plot_impact_flow()` | How much positive and negative SHAP pressure is generated by each feature in each segment? |
| **02 – Comparative Impact Atlas** | `plot_comparative_atlas()` | Which features have systematically different signed contributions across segments? |
| **04 – Segment Diagnostic Dashboard** | `plot_segment_dashboard()` | Which features explain a selected group's higher/lower mean raw prediction compared with the portfolio? |

Interactive charts are built with Plotly and exported as **standalone HTML with Plotly's JS embedded**. No server, LLM, web request, or API key is needed to open them.

## Usage A: directly from a trained LightGBM/XGBoost model

```python
from segment_impact_profiler import SegmentImpactReport

# df contains the exact feature columns seen by the model + age_band,
# predicted_pd, optional sampling_weight, and optionally raw_margin.
report = SegmentImpactReport.from_model(
    model=trained_model,
    data=df,
    feature_cols=feature_columns,  # exact model order!
    segment_col="age_band",       # or "risk_group", "occupation", etc.
    score_col="predicted_pd",     # optional, for summaries only
    weight_col="sampling_weight", # optional; handles sampled populations
    raw_margin_col="raw_margin",  # optional; verifies SHAP additivity
    higher_output_is_riskier=True,
)

report.plot_impact_flow(top_n=6).show()
report.plot_comparative_atlas(top_n=10).show()
# Focus on specified features when a dominant predictor compresses the others:
report.plot_comparative_atlas(features=["Debt-to-income ratio", "Credit utilization"]).show()
report.plot_segment_dashboard(top_n=9).show()
report.export("my_reports", prefix="age_band")

# The tables are available for validation and further exploration:
report.impacts.head()  # feature x group
report.segments        # population share, n, mean score, mean raw margin
report.impact_for("60–69")
```

## Usage B: from cached SHAP values (recommended when analyzing many segmentations)

```python
import shap
from segment_impact_profiler import SegmentImpactReport

explainer = shap.TreeExplainer(trained_model, model_output="raw")
explanation = explainer(df[feature_columns])
# For standard binary LightGBM/XGBoost raw margin:
values = explanation.values
baselines = explanation.base_values
# If values are 3D, select the target class axis appropriately.

for col in ["age_band", "risk_group", "employment_type"]:
    report = SegmentImpactReport.from_shap(
        data=df,
        shap_values=values,
        feature_names=feature_columns,
        segment_col=col,
        base_values=baselines,
        weight_col="sampling_weight",
        score_col="predicted_pd",
    )
    report.export(f"reports/{col}", prefix=col)
```

### Metric definitions

Let `φᵢⱼ` be the risk-oriented raw-margin SHAP contribution of feature `j` to individual `i`, and `wᵢ` its optional population weight.

- `mean_shap` = weighted mean of `φᵢⱼ` (direction and net effect)
- `mean_abs_shap` = weighted mean of `|φᵢⱼ|` (strength regardless of direction)
- `mean_positive` = weighted mean of `max(φᵢⱼ, 0)` (risk-increasing SHAP magnitude)
- `mean_negative_magnitude` = weighted mean of `max(-φᵢⱼ, 0)` (risk-reducing SHAP magnitude)
- `positive_share` = weighted proportion of rows where `φᵢⱼ > 0`
- `delta_vs_overall` = segment mean SHAP minus portfolio mean SHAP
- `direction_consistency` = `abs(mean_shap) / mean_abs_shap` (0 means extensive cancellation, 1 means same direction for almost all impactful observations)

Checks: `mean_shap = mean_positive - mean_negative_magnitude`, and
`mean_abs_shap = mean_positive + mean_negative_magnitude`.

### Waterfall identity

For a selected group `g`:

```
mean(raw_margin | g) - mean(raw_margin | portfolio)
  = Σ_features [mean(SHAP_j | g) - mean(SHAP_j | portfolio)]
  + [mean(base_value | g) - mean(base_value | portfolio)]
```

When SHAP baselines are constant (standard TreeExplainer), the last term is zero.
This identity holds for **mean raw margins** with consistent weights and the
same explainer baseline; it does **not** generally hold for average probability.
The right-hand side is the decomposition displayed in the waterfall chart.

### What Sankey widths actually mean

A link is the weighted **average magnitude of risk-increasing or risk-reducing
SHAP contributions**, optionally multiplied by a group's portfolio share.
It is *not* the fraction of borrowers flowing to an outcome class.
The `portfolio_weighted=False` default makes each group's link strengths comparable
independently of its size. Use `portfolio_weighted=True` to emphasize how much
of total portfolio attribution magnitude is contributed by each group.

### Credit-risk modeling cautions

1. The default assumes **positive raw model outputs mean higher modeled risk**.
   If the model's output has the opposite direction, use
   `higher_output_is_riskier=False`; the entire decomposition is sign-flipped.
   The optional `score_col` is only summarized, not transformed or assumed aligned.
2. SHAP directions refer to contributions relative to an explainer baseline;
   they do **not** necessarily mean that higher *values* of a feature increase risk.
   Feature-value dependence plots are a possible future addition.
3. SHAP explains **model predictions, not causal effects**. Correlated features,
   proxies, interactions, and alternative SHAP dependence assumptions matter.
4. Risk group segmentation is endogenous to the model score; differences between
   risk groups are descriptive, not independent evidence of generalization.
5. Only pass model features in the **exact training order**. SHAP rows and
   metadata must align exactly. Avoid post-outcome/leaking features.
6. SHAP can be expensive on very large populations. Sample responsibly and use
   `weight_col` when the data have valid expansion weights. Using different
   samples/baselines can make separate reports non-comparable.
7. Feature names refer to **model input columns**. One-hot or derived columns
   may be grouped into business concepts in a later release.
8. `max_additivity_error` checks reconstruction against actual raw model
   predictions when `raw_margin_col` is provided.

## Artifacts

Each `.export()` produces three HTML files and two CSV tables. The `demo_reports`
folder contains an end-to-end synthetic example. The `tests` directory checks
weighted aggregation, additivity, signs, output-shape handling, and offline exports.
